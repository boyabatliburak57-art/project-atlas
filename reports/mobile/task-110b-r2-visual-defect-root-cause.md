# TASK-110B-R2 Visual Defect Root Cause

This audit was recorded before the TASK-110B-R2 presentation fix. The approved five-tab
information architecture and canonical route ownership are unchanged.

| Defect                                    | Screen                                                               | Theme      | Device               | Root Cause                                                                                                                               | Shared Primitive                               | Fix Scope                                                                | Regression Risk                              |
| ----------------------------------------- | -------------------------------------------------------------------- | ---------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| Top safe-area collision                   | Global Search, Smart Inbox, Scanner and other feature/detail screens | Light      | iPhone 17 / iOS 26.5 | Feature-local `ScrollView` shells render directly below a headerless Expo Router stack and do not consume the provider's top inset       | New shared app-level `SafeAreaScrollScreen`    | Replace feature-local scroll shells; provider remains root-owned         | Medium: affects existing feature chrome only |
| Dynamic Island/status-bar collision       | Smart Inbox and Scanner                                              | Light      | iPhone 17 / iOS 26.5 | Same missing top-inset owner; large title is painted in the system exclusion region                                                      | `SafeAreaScrollScreen`                         | Shared screen shell                                                      | Medium                                       |
| Bottom safe-area/home-indicator collision | Bottom navigation contract                                           | Light/Dark | iPhone 17 / iOS 26.5 | Custom `BottomNavigation` accepts an inset but `AtlasTabBar` always uses its default zero value                                          | `BottomNavigation` + tab layout                | Pass provider bottom inset once from tab layout                          | Low                                          |
| Dark header contrast                      | Home, Markets and Radar hubs                                         | Dark       | iPhone 17 / iOS 26.5 | Header action glyphs are raw `Link` text without theme foreground/background semantics                                                   | `AppHeader`, `GlobalActionButton`              | Use semantic header tokens and the shared action primitive               | Low                                          |
| Header icon contrast                      | Five hubs                                                            | Dark       | iPhone 17 / iOS 26.5 | Global action and tab glyph colors fall back to platform black                                                                           | `GlobalActionButton`, `AtlasTabBar`            | Bind glyphs to semantic theme colors                                     | Low                                          |
| Scanner content/header collision          | Scanner via Radar                                                    | Light      | iPhone 17 / iOS 26.5 | Scanner's local `Screen` bypasses safe-area ownership                                                                                    | `SafeAreaScrollScreen`                         | Replace the local wrapper only; scanner business logic remains unchanged | Medium                                       |
| Scanner bottom-navigation overlap         | Scanner via Radar                                                    | Light      | iPhone 17 / iOS 26.5 | Not reproduced in the reviewed candidate, but protection relies on a feature-local `paddingBottom: 120` rather than the navigation owner | `SafeAreaScrollScreen`, `BottomNavigation`     | Remove the magic-number dependency through shared inset ownership        | Medium                                       |
| Scanner spacing regression                | Scanner via Radar                                                    | Light      | iPhone 17 / iOS 26.5 | The missing top inset shifts the whole screen upward; the internal scanner spacing scale itself is unchanged                             | `SafeAreaScrollScreen`                         | Shared shell only                                                        | Low                                          |
| Duplicated inset/padding risk             | Hub and feature screens                                              | Light/Dark | iPhone 17 / iOS 26.5 | Hubs use `SafeAreaView`, feature screens use unrelated padding, and the tab bar ignores its supported inset parameter                    | Root provider, shared screen shell, tab layout | One owner per edge, documented in the safe-area contract                 | Medium                                       |

Root cause conclusion: this is one shared screen-shell ownership defect plus one shared semantic
header-color defect. It must not be fixed with per-screen iPhone constants or Scanner-only hacks.

Post-fix verification: required safe-area collisions `0`, dark-header contrast defects `0`, Scanner
visual regressions `0`, and duplicated/magic bottom-inset ownership `0`. The shared contract is
documented in `docs/mobile/MOBILE_SAFE_AREA_CONTRACT.md`.

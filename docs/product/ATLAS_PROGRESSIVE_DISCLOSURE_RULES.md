# Atlas Progressive Disclosure Rules

1. A hub answers one user question; it is not a feature catalog.
2. The first viewport contains at most five to seven meaningful groups.
3. Order is primary attention/action, recent or personalized context, categories, then optional
   detail through “see all”.
4. Data tables expose summary first and detail on demand; numeric values use tabular alignment.
5. A card must contain real information or a useful action. Decorative cards and icon walls are
   prohibited.
6. Unimplemented intelligence features stay hidden in customer builds. A reviewed unavailable
   state is allowed only when it helps explain a capability already requested by the user.
7. Provider, license, configuration and freshness states are truthful and fail closed; fake
   production data is prohibited.
8. Contextual shortcuts always target the canonical owner route.
9. Common navigation depth is three. Builders and resource detail may go deeper only when the
   workflow requires it and a reliable back path remains.
10. Atlas uses the shared mobile tokens and primitives. It must remain a finance-professional data
    product, not a chatbot or generic AI-tool launcher.
